# Monorepo review, 2026-09-13

The review covers the first-party **ctbrowser and ctcompile monorepo**, including
public headers, implementation, tools, tests, examples, build configuration and
documentation. It found two P1 lifetime/storage defects, six P2 correctness or
tooling defects, three architectural improvements, and five small simplifications.
The native DOM change's maintainability finding was fixed in **53a8f49a**.
The other findings below remain open; passing the normal tests does not clear them.

Reviewed state: **03fa27f6** plus **f6d61d2a**, **9a67fd2b**, **9e5888c3** and
**53a8f49a** in the isolated native worktree. All open implementation findings
predate this session; their cited code is unchanged from the base.

## Correctness and API safety findings

### R1 — P1: scheduler destroys worker state before joining workers

`ctbrowser/lib/Core/scheduler.cpp:17` requests stop and notifies, then leaves the
destructor body. In `ctbrowser/include/ctbrowser/core/scheduler.hpp:97`,
`workers_` precedes `pending_`, `idle_mutex_`, `idle_` and `stopping_`. Reverse
member destruction destroys that synchronization state before the jthread
members join. A notified worker can still reacquire the mutex or evaluate the
predicate at `scheduler.cpp:80`; notification does not wait for completion.
The application constructs a local scheduler in `lib/App/app/run.cpp:319`.

Join workers while their synchronization state remains alive, after stop and
notification. Check partially constructed pools as well: member ordering and
an interruptible wait must handle thread-construction failure. Validate repeated
idle and busy pool teardown under a race/lifetime check. **Evidence: source and
C++ destruction order; no observed sanitizer failure.**

### R2 — P1: slab insertion indexes beyond its fixed directory at capacity

`ctbrowser/include/ctbrowser/core/slab.hpp:130` computes the chunk index and
uses `directory_[chunk]` without checking `max_chunks`. With 1,024 chunks of
4,096 slots, insertion **4,194,305** indexes element 1,024 of the fixed array.
The guard in `locate()` occurs after this invalid access and cannot protect it.
`document::create_element()` at `lib/DOM/document.cpp:332` reaches `nodes_.insert()`
directly; the document retains nodes even if callers discard handles.

Check the terminal capacity before indexing or publishing capacity, and give
allocation/capacity failure a defined outcome. Preserve slot reuse at the limit.
**Evidence: deterministic index calculation and caller trace; not executed.**

### R3 — P2: Canvas image-data numbers are narrowed and added before validation

`ctbrowser/lib/Shell/bindings/canvas.cpp:434` casts arbitrary JS numbers to
`int`; NaN, infinity and out-of-range values make that cast undefined. Clamping
afterward is too late. At line 452, the small request
`getImageData(2147483647, 0, 2, 1)` computes `INT_MAX + 1` on its second pixel
before the surface bounds check. `putImageData` repeats unchecked coordinate
addition at lines 492–493. `raster/surface.hpp:94` has related float-to-int
rounding before clipping.

Apply the appropriate WebIDL conversion before narrowing, use checked/wider
coordinate arithmetic, then clip. Cover small boundary inputs and invalid
floating values; huge allocations are unnecessary. **Evidence: reachable source
arithmetic; no memory-corruption exploit or sanitizer result claimed.**

### R4 — P2: HTTP caps silently produce successful truncated responses

`ctbrowser/lib/Shell/net/net.cpp:69` copies at most `max_bytes` but returns all
offered bytes to libcurl, with no truncation status. A 200 response containing
`AB` with `max_bytes = 1` therefore appears successful with body `A`.
`lib/Shell/bindings/resources.cpp:408` checks only `completed()` before creating
the JS Response. Zero cap can turn a nonempty response into successful emptiness;
discarded bytes continue downloading. The default cap has the same contract.

This behavior is intentional in the implementation comment, but the public
result hides it from callers. Reject an exceeded cap or expose truncation and
require complete-resource consumers to reject it. **Evidence: callback and fetch
path inspection; no local-server experiment was run.**

### R5 — P2: asset loading allocates from a filesystem error sentinel

`ctbrowser/include/ctbrowser/shell/page/assets.hpp:180` passes
`file_size(path, failed)` to `resize` before checking `failed`. If a path is
removed/replaced after opening, the pathname stat can fail with `uintmax_t(-1)`;
the attempted huge allocation throws before the intended error return. Fetch
uses this loader without translating that exception into resource failure.

Check the size and representability before allocating, and prefer sizing the
opened stream rather than restatting its pathname. **Evidence: error-order and
caller trace; the filesystem race was not exercised.**

### R6 — P2: the packaging CLI reports success after output failure

`ctcompile/tools/ctcompile/ctcompile.cpp:431` checks opening its output but not
the write/flush/close result. The optional manifest at line 446 repeats this.
The streams do not enable exceptions, so the outer catch does not help. A full
disk or failed buffered flush can reach the success message and zero exit code.

Explicitly close/flush and check both outputs, with a defined partial-file
policy. A valid bundle directed to Linux `/dev/full` is a small regression case.
**Evidence: stream-state/control-flow inspection; that CLI case was not run.**

### R7 — P2: startup baselines can label remote code with an unrelated local commit

`tools/check/baseline.py:87` builds the already-present remote tree without
synchronizing or verifying source identity. Line 100 then records the local
checkout's `git rev-parse HEAD`. After a branch change, local edits, or another
agent's devbox synchronization, timings can be attributed to code that was not
measured. The recorded build flags are also a literal description at line 71.

Record verified remote input identity/dirty state and actual configuration, or
require and verify a synchronized input manifest before measurement. A Python-only
mock check demonstrated a remote-tree-B result labeled local-tree-A with no
remote revision/hash check. This is a data-flow check, not a new benchmark.

### R8 — P2: a stalled comparison daemon can hang its clients indefinitely

`tools/check/compare.py:649` creates a socket with no timeout, then blocks in
`readline()` at line 654. Its daemon handles one connection at a time and also
blocks on an unlimited read at line 617. Startup waits on child stdout at line
210 without a deadline. `css-parity.py:707` and `:751` call stop without a
subprocess timeout, so one stalled session can block a complete parity run and
its cleanup.

Use one bounded request/startup deadline and ensure failure cleanup releases
children and sockets. Reuse the deadline approach already present in
`tools/wpt/run-wpt.py:295`. A bounded loopback check confirmed that request stays
blocked while the peer withholds its reply and completes only after the reply
is released. Source inspection establishes that no timeout limits that wait.

## Architectural improvements

- **One CSS shorthand grammar.** `style/engine.hpp:273` contains about 282 lines
  of expansion alongside a second implementation in
  `lib/Style/css/properties/shorthands.cpp:60`. The cascade calls the former
  after substitution; CSSOM setters call the latter. Consolidate shared expansion
  into the existing Style core, retaining caller-specific validation timing,
  ownership, aliases and cascade ordering. Replacing one whole path blindly is
  not behavior-preserving.
- **DOM-owned shadow identity.** `shell/bindings.hpp:1892` owns shadow-root/host
  maps used by event propagation, retargeting, styles, wrappers and adoption.
  Move the sparse relationships and native tree queries into `document`, which
  already uses a side table for template contents. Keep JS conversion, wrappers
  and exceptions in adapters. This is a concrete next API extraction, without
  introducing a second shadow graph or fields on every node.
- **Style-owned easing/interpolation.** The ordinary arithmetic and string
  operations at `lib/Shell/bindings/animations.cpp:74` through roughly line 287
  sit beside Promise/GC handling. Lift that existing implementation into public
  Style code; keep decoding and Promise state in the binding. Existing timing,
  extrapolation, steps and interpolation tests must preserve behavior.

Ordinary-page asset lookup also permits filesystem fallback by design, even
with a document root; `network = false` does not confine disk reads. Packaged
launchers enable sealed assets. Embedders must treat the ordinary configuration
as trusted local application loading, not as an untrusted-page sandbox. Changing
that capability/default is a separate semantic decision, not part of this
behavior-preserving native extraction.

For Python tooling, `compare.py:696` manually provisions and reexecutes a venv,
with an unrecorded Playwright/browser version. When that tool's setup is next
changed, declare its dependency and record the browser version used for parity;
uv can replace the bespoke environment setup. No whole-repo tool migration or
new dependencies were applied by this review.

## Ponytail: ranked simplifications

applied diffs. All current guards, whitespace sets and observable behavior must
remain. No tests, backends, vendor dependencies or historical handoffs are
counted as removable.

- `shrink:` Replace duplicate ASCII hex/case/trim loops with existing core
  `hex_value`, `ascii_iequals`, `ascii_upper_in_place` and exact-set `trim`.
  **19 lines**. `Style/css/token.cpp:43,542`, `Shell/bindings/element/wrapper.cpp:155`,
  `Style/engine.cpp:644`.
- `delete:` Remove unused `CTBROWSER_GLM_INCLUDE_DIR` discovery/documentation;
  there is no consumer. **13 lines**. `cmake/toolchains/windows-x86_64.cmake:14,70`.
  Keep Brew's GLM provision, which explicitly serves other repositories.
- `delete:` Remove obsolete per-binding capture-depth fields, transport and
  minimum assignment; retain the current `nestingOf` removal order and its

  `ClosureLifting/Bindings.cpp:465` under `ctcompile/lib/CTNative/Lowering`.

  `std::countr_zero(mantissa)` in the existing halfway formula, retaining zero
  and nonfinite guards. **4 net lines**. `ctbrowser/lib/Script/number_format.cpp:111`.
- `stdlib:` Replace the fixed-width manifest hex buffer/fallback with
  `std::format("0x{:016x}", value)`. **3 net lines**.
  `ctcompile/lib/Support/Manifest.cpp:13`.
